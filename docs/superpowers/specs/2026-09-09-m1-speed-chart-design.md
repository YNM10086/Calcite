## 一、目标与非目标

### 目标

在 M1 已完成「轨迹列表 + 地球画线 + 时间轴回放」的基础上，补上**与回放联动的速度/海拔曲线**：

1. 选中轨迹后，底部出现上下两张图：上为速度、下为海拔，**共用同一根时间轴**
2. 播放时一条竖直游标跟着白点走
3. 鼠标悬停显示该时刻的「时间 · 速度 · 海拔」
4. 点击曲线任意位置，跳到那一刻（地球上的白点跟着跳）

### 非目标（本次不做，YAGNI）

| 不做的事 | 理由 |
|---|---|
| 缩放 / 框选 / 平移时间轴 | 121 个点全貌一屏放得下，用不到 |
| 导出图片 / 复制数据 | 作品集展示不需要 |
| 多条轨迹曲线对比 | 属于 M2 相似度分析的范畴 |
| 速度平滑滤波 | 示例数据是插值生成的，本身就很平滑；真实数据出现毛刺时再加 |
| 曲线折叠 / 显示开关 | 用户明确选了 B（通栏双图）而不是 C（可折叠浮层） |
| 加速度 / 坡度等派生指标 | 先把两个基础指标做扎实 |

## 二、数据来源与空值

曲线只吃 `GET /api/tracks/{id}` 已经返回的字段，**后端和接口完全不用改**：

| 曲线 | 字段 | 单位 | 现状 |
|---|---|---|---|
| 速度 | `points[].speedMps` | 米/秒 | 120/121 个点有值 |
| 海拔 | `points[].elevationM` | 米 | 121/121 个点有值 |
| 横轴 | `points[].recordedAt` | ISO 8601 | 121/121 个点有值 |

**空值约定**：`seq = 0` 的 `speedMps` 为 `null`（它没有「前一个点」，算不出位移）。
这不是缺陷，是真实 GPS 数据的常态。处理方式：

- 速度序列**跳过 null**，线从第 2 个点开始画
- 悬停/游标落在 null 点上时，速度显示 `—`，不显示 `0`
- 若整条轨迹 `speedMps` 全为 null → 只画海拔图，并在速度图位置显示一行提示
  「这条轨迹没有速度数据」

## 三、关键决定

### 3.1 上下双图，而不是双 Y 轴叠一张图

速度和海拔量纲完全不同（3 m/s vs 40 m）。叠在一张图里就得用左右两套 Y 轴，
读图的人要在两套刻度之间来回换算，而且两条线交叉时会产生「速度超过海拔了」这种假象。

上下两张图**共用同一根横轴**、各自独立 Y 轴，代价是多占 112px 绘图高度（连刻度共 140px），换来的是「一眼能读」。
用户在三选一里明确选了这一种。

### 3.2 横轴用时间，不用点序号

如果横轴按「第几个点」等距排布，时间间隔不均匀的真实数据（GPS 丢星后一次补 3 分钟）
会被画成匀速，属于撒谎。

所以横轴的 `x` 由 `(ms - startMs) / (endMs - startMs)` 决定。示例数据每 25 秒一个点，
两种画法结果一样；换真实数据时才看得出区别——这是**为以后留的正确性**。

### 3.3 手写 SVG，零依赖

| 方案 | 体积 | 取舍 |
|---|---|---|
| **手写 SVG（选它）** | 0 | 全权掌控游标/点击交互；每行都能读懂；复用已有 Playwright+Pillow 验收方式。代价：坐标轴、网格、悬停提示要自己写 |
| uPlot | ~48 KB | 命令式 API，在 Vue 里要自己写集成层，样式也要手调 |
| ECharts | ~1 MB | 功能全，但给 121 个点加 1MB 依赖（当前包已 4.2MB）是过度工程 |

决定性的理由：这个功能的核心价值是**和 Cesium 时钟双向联动**，不是「画一条线」。
交互自己写最直接；而画线部分只有 121 个点，用不上任何库的性能。

### 3.4 宽度用 `ResizeObserver` 量真实像素

SVG 若用固定 `viewBox` + 拉伸填满容器，圆点会变成椭圆、线宽会跟着变（上一版演示图
正是这样，2.5px 的点被横向放大成 8px，看起来像「工」字）。

所以：**监听容器实际宽度，用像素坐标画**。这样 `r="2"` 就是真正的 2 像素，
点击位置换算成时刻也只是一次除法。

## 四、组件与数据流

### 4.1 文件划分

| 文件 | 职责 | 依赖 | 可测性 |
|---|---|---|---|
| `frontend/src/lib/chart.js`（新） | 纯计算：序列提取、Y 轴范围、刻度、SVG 路径字符串、最近点、格式化 | 无（不碰 Vue / Cesium） | node 直接测 |
| `frontend/src/components/SpeedChart.vue`（新） | 纯展示：props 进、SVG 出，自己不存状态 | Vue + chart.js | Playwright 截图 |
| `frontend/src/App.vue`（改） | 唯一的「大脑」：持有 `currentMs`，把曲线和地球接起来 | — | 端到端 |

与已完成的 `playback.js` + `TrackPlayer.vue` 保持同一套结构：**计算与显示分离**，
计算部分永远能用 node 秒测。

### 4.2 数据流

```
detail.points（每点含 recordedAt / speedMps / elevationM）
        ↓  :points :currentMs :startMs :endMs
SpeedChart.vue
  ├─ chart.js：算刻度、算范围、生成 path、找最近点
  └─ 渲染 <svg>：速度图 + 海拔图 + 游标 + 悬停提示
        ↑ @seek(ms)
App.vue：seekTo(ms)  ← 与拖动进度条**完全同一个函数**
        ↓
CesiumGlobe.seekTo(ms) → clock.currentTime 改变 → 白点跳过去
        ↓ time-change（节流 100ms）
App.vue：currentMs → 曲线游标位置
```

**关键点**：曲线点击和进度条拖动走同一个 `seekTo`，所以两条路径的行为永远一致，
不存在「点曲线能跳、拖进度条不能跳」这种分裂。

### 4.3 `chart.js` 的纯函数清单

| 函数 | 作用 |
|---|---|
| `seriesOf(points, key)` | 抽出 `[{ms, value}]`，跳过 null |
| `domainOf(values, padRatio)` | 算 Y 轴范围（含上下留白） |
| `niceTicks(min, max, count)` | 生成取整后的刻度（避免 `37.4213` 这种标签） |
| `timeTicks(startMs, endMs, count)` | 生成时间轴刻度 |
| `pathOf(series, xOf, yOf)` | 生成 SVG `path` 的 `d` 字符串 |
| `scaleX(startMs, endMs, left, width)` | 时间 → 像素 x |
| `scaleY(domain, top, height)` | 数值 → 像素 y |
| `msAtX(x, startMs, endMs, left, width)` | 像素 x → 时间（点击/悬停反算） |
| `valueAt(series, ms)` | 线性插值取某时刻的值（游标落点 + 悬停读数） |
| `tickDigits(ticks)` | 推断刻度该保留几位小数 |
| `formatTick(ms)` / `formatValue(v, digits)` | 标签格式化 |

## 五、视觉规范

### 5.1 尺寸与位置

| 元素 | 尺寸 / 位置 |
|---|---|
| 速度图 | 高 56px，通栏 |
| 海拔图 | 高 56px，通栏，紧贴速度图下方 |
| 时间轴刻度行 | 高 20px |
| 图表整体 | 高 140px，`position: absolute; bottom: 46px`（正好压在回放条上方） |
| 左下角状态文字 | `bottom` 从 62px 上移到 **194px**（46 + 140 + 8） |

### 5.2 颜色（沿用现有配色，不引入新色系）

| 用途 | 色值 | 依据 |
|---|---|---|
| 速度线 | `#7ee0a6` | 与地球上的起点标记同色，呼应 |
| 海拔线 | `#ffb95e` | 暖橙，与蓝绿色速度线区分度高 |
| 网格线 | `rgba(127, 209, 255, 0.12)` | 现有面板边框同色系 |
| 刻度文字 | `#93a4bb` | 现有次要文字色 |
| 游标线 | `#ffffff`，透明度 0.7 | 中性，不与两条数据线抢 |
| 交点微点 | `#ffffff` | 同游标 |
| 悬停提示背景 | `rgba(10, 16, 26, 0.92)` | 现有面板底色 |

### 5.3 游标（用户明确要求改细）

上一版演示图里游标看起来像「工」字并遮挡数据线。规范如下：

| 属性 | 值 | 理由 |
|---|---|---|
| 线宽 | 1px 虚线（`stroke-dasharray: 4 3`） | 细到不抢戏 |
| 透明度 | 0.7 | 交叉处仍能看见底下的线 |
| 绘制顺序 | **画在数据线之前**（即位于下层） | 数据线永远压在上面，物理上不可能被遮挡 |
| 交点标记 | **半径 2px 白色微点**（直径 4px） | 用户三选一里选了「2px 微点」 |

### 5.4 验收用的 `data-testid`

| testid | 挂在谁身上 |
|---|---|
| `speed-chart` | 图表根容器 |
| `chart-speed` | 速度那张图的 `<svg>` |
| `chart-elevation` | 海拔那张图的 `<svg>` |
| `chart-playhead` | 游标竖线 |
| `chart-tooltip` | 悬停提示框 |

## 六、交互

| 交互 | 行为 | 实现要点 |
|---|---|---|
| 游标跟随 | 播放时竖直虚线随白点移动 | 复用已有的 `time-change` 事件（节流 100ms），不新增定时器 |
| 悬停 | 显示「07:49:12 · 速度 3.15 m/s · 海拔 41.6 m」 | `mousemove` 取 `offsetX` → `msAtX` 换算成 ms → `valueAt` 插值 |
| 点击 | 跳到该时刻 | 同一个 `offsetX` 换算 → `emit('seek', ms)` |
| 拖出图表 | 隐藏悬停提示 | `mouseleave` |

三条交互都只在**图表区域内部**生效，不影响地球的鼠标操作。

## 七、边界情况

| 情况 | 表现 |
|---|---|
| 未选中轨迹 | 整个图表不渲染 |
| 点数 < 2 | 整个图表不渲染 |
| 缺少时间戳（`timeRange` 为 null） | 整个图表不渲染（复用 `playback.js` 的 `canPlay(points)`，与回放条同源判断） |
| 速度整列为 null | 只画海拔图，速度图位置显示「这条轨迹没有速度数据」 |
| 海拔整列为 null | 对称处理，显示「这条轨迹没有海拔数据」 |
| 单个点的值为 null | 该点不参与画线；游标落在它上面时数值显示 `—` |
| 所有值相同（如速度恒为 3.0） | Y 轴范围退化时强制撑开一个最小跨度，避免除零 |
| 窗口宽度变化 | `ResizeObserver` 重算，不重建数据 |

## 八、验收方式

沿用项目已确立的两层验收（不引入任何测试框架）：

### 8.1 纯计算层 —— `frontend/scripts/check-chart.mjs`（node 内置 `assert`）

- 零依赖、秒级、打印 `✓ / ✗`，失败时 `process.exitCode = 1`
- 覆盖：`seriesOf` 跳空值、`domainOf` 退化保护、`niceTicks` 取整正确、
  `pathOf` 生成的 `d` 合法、`scaleX`/`scaleY` 端点、`msAtX` 夹紧、`valueAt` 插值与两端、`tickDigits` 位数、`formatTick` / `formatValue` 格式
- 在 `package.json` 加脚本：`"check:chart": "node scripts/check-chart.mjs"`

### 8.2 真实浏览器层 —— Playwright + Pillow

| 检查项 | 断言 |
|---|---|
| 图表出现 | 选中轨迹后存在 `[data-testid="speed-chart"]` |
| 两条线都画了 | 绿色像素 > 0 **且** 橙色像素 > 0 |
| 游标会动 | 播放 4 秒，前后两张截图里白色游标的 x 坐标差 > 20px（**只在图表所在的像素带内搜索**，避免误抓地球上的白色移动点） |
| 点击跳转 | 点击图表 80% 宽度处，**回放条上的时钟**（`[data-testid="clock"]`）变成 `08:10:00` |
| 悬停读数 | 悬停后 `[data-testid="chart-tooltip"]` 的文本匹配 `\d{2}:\d{2}:\d{2}` |
| 游标不遮挡数据线 | 游标穿过数据线处，该像素仍满足绿色/橙色判据（不被白色覆盖） |
| 控制台 | 零报错 |

**像素判据**（Pillow，只在图表像素带内统计，`y ∈ [视口高 - 186, 视口高 - 46)`）：

- 绿色速度线：`g ≥ 180 且 r ≤ 150 且 b ≤ 180`，像素数 > 50
- 橙色海拔线：`r ≥ 200 且 100 ≤ g ≤ 200 且 b ≤ 130`，像素数 > 50
- 白色游标：`r, g, b ≥ 230`，取该带内白色像素 x 坐标的中位数

> 无头 Chrome 的 `--virtual-time-budget` 截图会漏掉 Cesium 异步几何体，
> 必须用 Playwright 真实等待——这一点在 M1 回放里已经踩过并记录。

## 九、风险与取舍

| 风险 | 应对 |
|---|---|
| 每 100ms 重渲染 SVG 可能掉帧 | 只改游标线的 `x` 坐标，不重建 path；Vue 的响应式只会重排这一个属性 |
| 悬停提示的定位在窗口边缘会溢出 | 提示框位置做左右夹紧（clamp） |
| 时间轴刻度太密导致文字重叠 | 按容器宽度动态决定刻度数量（宽度 ÷ 80px） |
| 以后真实数据出现毛刺 | 非目标里已排除平滑；届时在 `chart.js` 加一层可选滤波，不影响组件 |
